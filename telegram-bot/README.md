# 🤖 ربات تلگرام امید عدلی — فروش، تحویل و پشتیبانی

ربات تلگرامی که **شماره مشتری را تأیید می‌کند**، **اشتراک محصولات دیجیتال را می‌فروشد**،
**رسید کارت‌به‌کارت را خودکار بررسی و تأیید می‌کند** و بعد از تأیید، **کد دسترسی را صادر/تمدید
و محصول را تحویل می‌دهد** — بدون اینکه ادمین سفارشی را دانه‌به‌دانه بررسی کند.

> ✅ **میزبانی پیشنهادی و پیاده‌سازی‌شده: Cloudflare Pages Functions**
> ربات روی همان سایتی که الان دارید اجرا می‌شود (`functions/api/telegram.ts`) و به همان
> دیتابیس D1 سایت وصل است. نتیجه: بعد از خرید، `tool_access` و `user_subscriptions`
> مستقیماً نوشته می‌شوند و پروفایل کاربر در سایت همان لحظه به‌روز می‌شود — بدون هیچ سرور جدا،
> همگام‌سازی، یا هزینه اضافه.

---

## 🎯 چه کاری انجام می‌دهد

| مرحله | جزئیات |
|---|---|
| 📱 **تأیید شماره** | دکمه «اشتراک شماره» (تأییدشده توسط تلگرام) یا ورود دستی + کد ۶ رقمی داخل چت |
| 🛒 **خرید** | انتخاب محصول (۴ محصول هوش مصنوعی) → انتخاب پلن (پایه/حرفه‌ای/VIP) → نمایش شماره کارت و مبلغ |
| 🧾 **رسید** | مشتری عکس رسید را می‌فرستد؛ مبلغ و شماره پیگیری از کپشن یا پیام بعدی خوانده می‌شود |
| 🤖 **تأیید خودکار** | ۱) شماره پیگیری معتبر و **تکراری نباشد** ۲) مبلغ با قیمت پلن بخواند (تومان یا ریال) ۳) عکس رسید با **بینایی ماشین** خوانده و تطبیق داده شود ۴) تاریخ رسید منطقی باشد |
| 🎁 **تحویل خودکار** | کد دسترسی صادر یا **تمدید** می‌شود (تمدید = افزودن به تاریخ انقضای فعلی، نه صفر کردن آن) + پیام تحویل با کد و لینک محصول |
| 👤 **سایت** | اگر شماره در سایت ثبت شده باشد، اشتراک در `user_subscriptions` و تایم‌لاین `user_activities` هم ثبت می‌شود |
| 🛡 **شبکه ایمنی** | رسید تکراری → رد خودکار؛ مبلغ ناهمخوان → «نیاز به بررسی» (هرگز خودکار تأیید نمی‌شود)؛ همه تصمیم‌ها به ادمین اطلاع داده می‌شود |
| 🛠 **پنل ادمین** | `/admin`، `/orders_pending` (با دکمه تأیید/رد)، `/broadcast`، `/stats` |
| 💬 **پشتیبانی** | پیام کاربر مستقیم برای ادمین‌ها فوروارد می‌شود |

## 🚀 راه‌اندازی (۱۰ دقیقه)

### ۱) ساخت ربات
1. [@BotFather](https://t.me/BotFather) → `/newbot` → توکن را کپی کنید
2. آیدی عددی خودتان: [@userinfobot](https://t.me/userinfobot)

> ⚠️ توکن را در چت/گیت‌هاب نفرستید. فقط در Secrets کلودفلر.

### ۲) تنظیم متغیرها در Cloudflare

**Cloudflare Dashboard → Workers & Pages → پروژه سایت → Settings → Environment variables**

| متغیر | الزامی | توضیح |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | ✅ | توکن BotFather — **Secret** |
| `TELEGRAM_WEBHOOK_SECRET` | ✅ | رشته تصادفی قوی (`openssl rand -hex 32`) — **Secret** |
| `TELEGRAM_ADMIN_IDS` | ✅ | آیدی عددی ادمین‌ها، با کاما: `123456789,987654321` |
| `BOT_CARD_NUMBER` | ✅ | شماره کارت برای کارت‌به‌کارت (مثلاً `6037-9911-1234-5678`) |
| `BOT_CARD_HOLDER` | ➖ | نام صاحب کارت |
| `GEMINI_API_KEY` | ⭐ | برای **تأیید خودکار با بینایی ماشین** — اگر سایت قبلاً این را دارد، همان استفاده می‌شود |
| `TELEGRAM_AUTO_APPROVE` | ➖ | `vision` (پیش‌فرض، امن‌ترین) \| `always` (بدون AI هم تأیید خودکار) \| `off` (همیشه دستی) |
| `TELEGRAM_VISION_MODEL` | ➖ | پیش‌فرض `gemini-2.5-flash` |
| `SITE_URL` | ➖ | پیش‌فرض `https://omidadli.com` |

> 💡 **اگر کلید `GEMINI_API_KEY` را نگذارید**، بررسی عکس انجام نمی‌شود و رسیدها با
> «نیاز به بررسی» برای شما می‌آیند. برای حالت کاملاً خودکار بدون AI،
> `TELEGRAM_AUTO_APPROVE=always` بگذارید (تأیید فقط بر اساس مبلغ + شماره پیگیری یکتا).

### ۳) ساخت جدول‌ها

```bash
npx wrangler d1 execute omidadli01-site-db --remote --file=migrations/0006_telegram_bot.sql
```
(ربات خودش هم در اولین اجرا جدول‌ها را می‌سازد؛ اجرای این دستور توصیه می‌شود.)

### ۴) ثبت webhook

```bash
curl "https://<دامنه-سایت>/api/telegram?setup=<TELEGRAM_WEBHOOK_SECRET>"
# {"ok":true,"webhookUrl":"https://<دامنه>/api/telegram", ...}
```

### ۵) بررسی سلامت

```bash
curl https://<دامنه-سایت>/api/telegram
# {"ok":true,"configured":{"token":true,"secret":true,"admins":1,"vision":true,...}}
```

### ۶) تست
در تلگرام به ربات `/start` بدهید → شماره را تأیید کنید → `/buy` → یک پلن بخرید →
عکس یک رسید واقعی (یا تستی) بفرستید و ببینید که خودکار تأیید و تحویل می‌شود.

## 🔌 پل ارتباطی سایت → تلگرام (تحویل خودکار بعد از خرید در سایت)

اگر پرداخت در سایت انجام شد (درگاه یا دستی)، این درخواست را از Pages Function بزنید تا
محصول در تلگرام مشتری تحویل شود و کد دسترسی صادر/تمدید شود:

```bash
curl -X POST https://<دامنه-سایت>/api/telegram/deliver \
  -H 'Content-Type: application/json' \
  -H "X-Bot-Webhook-Secret: $TELEGRAM_WEBHOOK_SECRET" \
  -d '{
    "phone": "09123456789",
    "productId": "business-therapist",
    "planId": "pro",
    "orderId": "ord_1234",
    "note": "خرید از سایت"
  }'
```

پاسخ: `{"ok":true,"deliveryId":"...","queued":false,"linked":true,"code":"ABC-1234","expiresAt":"..."}`

- اگر مشتری تلگرامش را تأیید کرده باشد → همان لحظه تحویل.
- اگر نه → `queued: true` و به‌محض تأیید شماره، خودکار تحویل می‌شود.
- اگر خودتان کد را صادر کرده‌اید، `code` و `expiresAt` را هم بفرستید تا فقط اطلاع‌رسانی کند.

نمونه کد سمت سایت در [`docs/TELEGRAM-BOT-PROMPT.md`](../docs/TELEGRAM-BOT-PROMPT.md) آمده است.

## 🖥 نسخه‌ی Node.js (سرور شخصی) — اختیاری

اگر ترجیح می‌دهید ربات روی سرور خودتان (VPS/PM2/Docker) اجرا شود و به کلودفلر وابسته نباشد،
پوشه‌ی `telegram-bot/` یک نسخه‌ی کامل Node.js (بدون هیچ وابستگی) دارد با همان قابلیت‌ها،
اما داده‌ها را در فایل‌های JSON نگه می‌دارد و به D1 سایت وصل نیست (تحویل محصول و
تأیید رسید کار می‌کند، ولی صدور خودکار `tool_access` سایت را ندارد).

```bash
cd telegram-bot
cp .env.example .env   # BOT_TOKEN و ADMIN_TG_IDS و WEBHOOK_SECRET
npm start              # long polling
npm test
```

استقرار ۲۴/۷: PM2 (`pm2 start bot.mjs --name tg-bot`) یا systemd.

**توصیه: نسخه‌ی Cloudflare را استفاده کنید** (بخش‌های ۱ تا ۶ بالا) چون هم‌دیتابیس با سایت است
و صفر هزینه‌ی سرور دارد.

## 🔐 امنیت

- توکن و secret فقط در Cloudflare Secrets (نه در کد، نه در گیت).
- webhook با هدر `X-Telegram-Bot-Api-Secret-Token` اعتبارسنجی می‌شود؛ پل سایت با `X-Bot-Webhook-Secret`.
- هر آپدیت با `update_id` یکتا ثبت می‌شود → تکرار/دوباره‌ارسال تلگرام باعث تحویل دوباره نمی‌شود.
- هر شماره پیگیری فقط یک‌بار می‌تواند پرداخت را تأیید کند.
- دستورهای ادمین فقط برای `TELEGRAM_ADMIN_IDS`.
- اگر توکن لو رفت: در BotFather دستور `/revoke`.

## ❓ عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| ربات جواب نمی‌دهد | `curl https://<دامنه>/api/telegram` → `configured.token` باید true باشد؛ webhook را با `?setup=` دوباره ثبت کنید |
| رسیدها همه «نیاز به بررسی» می‌آیند | `GEMINI_API_KEY` تنظیم نیست یا رسید خوانا نیست؛ یا `TELEGRAM_AUTO_APPROVE=always` بگذارید |
| «شماره در سایت ثبت نشده» در پیام ادمین | کاربر با آن شماره در سایت حساب ندارد؛ کد محصول صادر شده و بعد از ثبت‌نام با همان شماره، پروفایل با درخواست بعدی همگام می‌شود |
| مبلغ تأیید نمی‌شود | رسیدها معمولاً **ریال** چاپ می‌شوند؛ سیستم ×۱۰ را در نظر می‌گیرد، اما اگر مبلغ پلن را تغییر داده‌اید و رسید مبلغ قدیمی دارد، بررسی دستی لازم است |
